* Syncing Another Machine After An Upgrade

Elpaca only reads `elpaca-lock.el` when installing a package, so pulling an upgrade leaves existing checkouts on their old commits until they are synced.

With `elpaca/` already present:

1. Quit Emacs
2. `git pull`
3. `scripts/upgrade-run.sh . elpaca-sync-to-lock.el` (add `--dry-run` to preview)
   - Checks out each package at its locked ref, fetching from origin, and rebuilds only what changed
   - Installs packages that are new in the lock file
4. Optional: `scripts/upgrade-run.sh . elpaca-check.el --label synced`, then confirm `var/upgrade/check-synced.md` shows no differences from the lock file
5. Start Emacs; the first launch is slower while rebuilt packages natively compile, and jinx compiles its module the first time a spell-checked buffer opens

If the sync fails with a `void-function` error inside elpaca, `eln-cache/` holds native-compiled elpaca files from a different elpaca version. Move them aside and sync again:

#+begin_src sh
mkdir -p ~/stale-eln && mv eln-cache/*/elpaca*.eln ~/stale-eln/
#+end_src

Without `elpaca/` (new machine): start Emacs; Elpaca installs everything at the locked refs.

Last resort: `./clean.sh`, then restart to rebuild everything from the lock file.

** Update process (notes.org)

- Rename `elpaca-lock.el` to `elpaca-lock.el.old`
- Go to `elpaca/repos` and run `for d in */; do (cd "$d" && git checkout $(git remote show origin 2>/dev/null | grep 'HEAD branch' | awk '{print $NF}') && git fetch); done`
- M-x `elpaca-fetch-all`
- Review as much as desired
- M-x `elpaca-pull-all`
- M-x `elpaca-write-lock-file`
- Restart and confirm

** Update process (init.el comments)

- elpaca-fetch / elpaca-fetch-all — only downloads remote commits, does not merge or rebuild
- elpaca-merge / elpaca-merge-all — merges changes (optionally fetches first), rebuilds
- elpaca-pull / elpaca-pull-all — fetch + merge + rebuild (aliased as elpaca-update / elpaca-update-all)

Safer update workflow:

1. M-x elpaca-fetch-all — download all new commits without changing anything
2. M-x elpaca-log-updates — review what changed (if available), or check elpaca-manager to see which packages have pending updates
3. M-x elpaca-pull-all — actually merge and rebuild when you're ready
4. Restart Emacs, verify things work
5. M-x elpaca-write-lock-file — regenerate the lock file
6. git diff elpaca-lock.el — review and commit
